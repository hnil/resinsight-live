# Fixes 2026-11-20

Defects from the live session of 2026-11-20 (Norne S2m vs the reference). Nothing is pushed.

| # | Defect | Cause | Fix | Where |
|---|---|---|---|---|
| 1 | A `.pvd` fracture surface did not follow the view's date (step 28 showed an early fracture) | `RimSurfaceInView::loadDataAndUpdate` used `.pvd` entry N for view step N | Each view step shows the last `.pvd` entry at or before its time (the case's days since start; else its dates counted from the first step). Legend range follows. So you can write every fracture step and keep few report steps | ResInsight `6ed34696c` |
| 2 | A project from `saveProject` had `$PathId_003$ $PathId_003$;` and opened with 0 time steps | `RimProject::writeProjectFile` swaps paths for ids, then returned early when the file could not be opened (missing folder), so the paths stayed as ids and the next save mapped each id to itself. Reproduced headless. The plugin's temp-project round trip is not the cause | Restore the paths on that early return (ResInsight); create the target folder before `saveProject` (plugin) | ResInsight `e30b9327b`, plugin `e6e3fbb` |
| 3 | Every surface active in every new view (21 legends); no way to drop a case | Plugin `ri_open` imported the companion `.pvd` a second time (ResInsight's `loadCase` already does); new views turn on every surface; scripting had no single-case close | `ri_surfaces` (show/hide/only/own_case per view), `ri_remove` (cases and surfaces); new views from `ri_open` / `ri_create_view` show only their case's surfaces; no double import. ResInsight: `Case.close()` scripting method (same as Close in the tree) | plugin `ad66ba5`, ResInsight `cb96d3402` |
| 4 | `ri_camera` / `ri_look_at` `direction` unclear | Code was right: it is the line of sight (eye towards target); `-0.9063,0.4226,0` looks along the normal of a strike-25° plane | Doc strings and README say so, with the strike formula | plugin `028d12a` |
